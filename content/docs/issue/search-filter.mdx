## 为什么值得学

Issue 一多就找不到。**GitHub 的 issue 搜索是一套真正的查询语言**（不是普通关键词搜索），掌握它，你能一句话问出「我名下、v1.0 里、还没做的高优先级 bug」。

## 核心查询词

| 查询 | 含义 |
| --- | --- |
| `is:issue` / `is:pr` | 只看 Issue 或只看 PR |
| `is:open` / `is:closed` | 状态过滤 |
| `label:bug` | 带某标签（多标签写多个 `label:`） |
| `-label:wontfixed` | 前缀 `-` 表示排除 |
| `assignee:@me` | 指派给我（也可写具体用户名） |
| `author:yongkong` | 由某人创建 |
| `milestone:"v1.0"` | 属于某里程碑 |
| `no:milestone` | 未归入任何里程碑 |
| `created:>2026-01-01` | 按创建时间 |
| `in:title 登录` | 只在标题里搜关键词 |

**空格 = AND**；多个 `label:` 默认是「同时满足」。

组合示例：

```text
is:open is:issue label:bug assignee:@me no:milestone
```

读作：*我还未关闭、未排进版本、且属于我的 bug。*

## 排序与保存

- 右上 **Sort** 可按 创建时间 / 更新时间 / 评论数 排。
- 搜索框结果满意后，点 **Save** 起个名，下次一键调用（团队常用这招做「待我 review 的 PR」快捷视图）。

## 动手清单

1. 进仓库 **Issues** 搜索框，粘贴：`is:open is:issue label:bug`，回车。
2. 再加一段 `assignee:@me`，观察结果如何收窄。
3. 用 `no:milestone` 找出「还没排进版本」的 Issue。
4. 把满意的一条搜索 **Save** 成 `我的待办`。
